= Slack Reactions Notifier

A simple Slack bot that notifies you when someone adds a reaction to your message.

== Features
- Captures `reaction_added` events.
- Notifies you via DM when someone reacts to your messages.
- Self-reaction debug mode.
- Configurable logging levels.
- Pydantic-based configuration.
- Dockerized setup.

== Configuration
The application is configured via environment variables or a `.env` file located in the project root (parent of the `app/` directory).

[cols="1,2,1"]
|===
| Variable | Description | Default

| SLACK_BOT_TOKEN | Your Slack Bot User OAuth Token (`xoxb-...`) | Required
| SLACK_APP_TOKEN | Your Slack App-Level Token (`xapp-...`) | Required
| MY_SLACK_ID | Your Slack Member ID (e.g., `U12345678`) | Required
| LOGGING_LEVEL | Logging level (DEBUG, INFO, WARNING, etc.) | INFO
| LOGGING_LEVEL_FOR_THIRD_PARTY_LIBS | Logging level for third-party libraries (slack_bolt, etc.) | WARNING
|===

=== Configuration Methods
The application supports two primary configuration methods:

1. **Build-time `.env` file**:
You can place a `.env` file in the project root before building the Docker image. The `Dockerfile` copies this file into the `/app` directory inside the container. This method is convenient for stable environments.

2. **Runtime Environment Variables**:
You can build the container with an empty or missing `.env` file and provide all necessary settings at runtime. Environment variables take precedence over values in the `.env` file. This is the recommended way to handle sensitive tokens.

Example of a startup script (`run_notifier.sh`) using runtime variables:

[source,bash]
----
#!/bin/bash
docker run -d \
  --name slack-reactions-notifier \
  -e SLACK_BOT_TOKEN="xoxb-your-bot-token" \
  -e SLACK_APP_TOKEN="xapp-your-app-token" \
  -e MY_SLACK_ID="U12345678" \
  -e LOGGING_LEVEL="INFO" \
  -e LOGGING_LEVEL_FOR_THIRD_PARTY_LIBS="WARNING" \
  slack-reactions-notifier
----

== Installation

=== Slack Setup Guide

This project follows the **"Bring Your Own App" (Mirror App)** pattern.
To protect your corporate credentials and avoid running a centralized server,
every user creates their own private mirror application in their Slack workspace.
This grants the script the exact same access level as your personal Slack account.

==== Step 1: Create Your Mirror App & Get `SLACK_APP_TOKEN`

. Go to link:https://api.slack.com/apps[api.slack.com/apps] and click *Create New App* -> *Blank app*.
. Name it (e.g., `my-reactions-notifier`) and select your development workspace.
. In the left menu, go to *Settings* -> *Socket Mode* and toggle *Enable Socket Mode* to *ON*.
. In the modal, name the token (e.g., `SocketToken`), click *Generate*, and copy the string starting with `xapp-...`.
  * Save this value as *`SLACK_APP_TOKEN`* in *.env*.

==== Step 2: Configure Scopes & Messages Tab

. Go to *Features* -> *OAuth & Permissions*.
  * Under *Bot Token Scopes*, add:
    ** `reactions:read` — to detect emoji reaction events.
    ** `chat:write` — to send direct messages back to you.
    ** `channels:history` — to monitor public channel history.
. Go to *Features* -> *Event Subscriptions*
  * toggle *Enable Events* to *ON*.
  * Under *Subscribe to bot events*
    ** add `reaction_added`
    ** click *Save Changes* at the bottom.
. Go to *Features* -> *App Home*.
  ** Under *Show Tabs*
     *** turn the *Messages Tab* *ON*
     *** check *"Allow users to send Slash commands and messages from the messages tab"*.
. Go to *Features* -> *OAuth & Permissions* -> *Redirect URLs*.
  ** Add `http://localhost:8000` and click *Save URL*.

==== Step 3: Install the App & Get Credentials

. Go to *Settings* -> *Install App*
  * click *Install to Workspace*, and authorize permissions.
  * Copy the *Bot User OAuth Token* starting with `xoxb-...`.
  * Save this value as *`SLACK_BOT_TOKEN`*.
. Go to *Settings* -> *Basic Information* -> *App Credentials*.
  * Copy your `Client ID` and `Client Secret` (click *Show*).
    You will need them for the interactive login script.

==== Step 4: Run Interactive Authentication

The interactive `auth.py` script starts a temporary local server, opens your browser,
and fetches your personal user token and unique user ID (`MY_SLACK_ID`)
without exposing them to third parties.

[source,bash]
----
# Set your mirror app credentials in the terminal
export SLACK_CLIENT_ID="your_client_id_here"
export SLACK_CLIENT_SECRET="your_client_secret_here"

# Launch the ephemeral auth server
python auth.py
----

Your browser will prompt you to authorize your mirror app. Click *Allow*.
A local success webpage will display your generated `SLACK_USER_TOKEN` (starts with `xoxp-...`)
and your `MY_SLACK_ID` (starts with `U...`).
Copy them into your production `.env` file and close the browser.

==== Step 5: Client Refresh & Verification

. **Force Refresh Slack Client**:
  ** Open your desktop Slack application and press `Ctrl + R` (Windows) or `Cmd + R` (Mac)
     to unblock the app's messaging interface.
. **Locate the App**:
  ** In the Slack left sidebar under *Apps*, find `my-reactions-notifier` and open its direct chat.
     Send any message to verify text input is fully unlocked.
. **Test the Handler**:
  ** Run your main notifier script. Post a message inside the bot's direct chat
     (or a public channel where you invited it via `/invite @my-reactions-notifier`)
     and add an emoji reaction.
     The handler will log the event to the screen and `logs/` directory,
     then send a notification to your DM.

=== Using Docker
1. Build the image:
[source,bash]
----
./docker_build.sh
----

2. Run the container:
[source,bash]
----
./docker_run.sh
----

=== Local Development
1. Install dependencies:
[source,bash]
----
pip install -r requirements.txt
----
(Note: It is recommended to use `uv` or `pip` with `pyproject.toml`)

2. Run the application:
[source,bash]
----
python -m app.slack_reaction_notifier
----

== Project Structure
- `app/slack_reaction_notifier.py`: Main entry point.
- `app/config.py`: Configuration management.
- `app/logs/`: Directory for log files.
- `Dockerfile`: Container definition.
- `pyproject.toml`: Project metadata and dependencies.
